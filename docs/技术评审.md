1. **统一入库管道**（`createFromClip` → job queue）避免三条入口各写一套逻辑。  
2. **向量后端可切换**（sqlite-vec | Lance）把 Windows 原生编译风险从「阻塞项」变成「M0 冒烟决策」。

6. **IPC 表** 已覆盖主路径，便于直接拆 Issue。

## 3. 必须修正（开工前）

### M1. 导入导出优先级与验收不一致

- 正文 §2.2 把打包导入导出放在 P1，但 §12 验收第 7 条已要求换机导入。  
- **裁定**：导入导出纳入 **M3（MVP 收尾）必做**，不进 P1。单文件 MD/TXT 导入可仍留 P1。

### M2. `schema.sql` 与 FTS / 向量落地缺口

1. `knowledge_items_fts` 使用 `content='knowledge_items'` 时，SQLite 要求 `knowledge_items` 有整数 `rowid`（默认有），但 **TEXT 主键表** 的 FTS 外连在部分查询下别扭；建议检索用 `fts MATCH` 后 `JOIN knowledge_items ON knowledge_items.rowid = fts.rowid`，并在文档写明。  
2. **缺少 sqlite-vec 虚拟表 DDL**（或明确「仅 Lance 时用 `chunk_vector_ref`」）。应在 `schema.sql` 增加注释块 + 迁移里按 backend 创建。  
3. `embeddings.bin`（方案）与 `embeddings.jsonl`（backup-format）不一致 → **统一为 `embeddings.jsonl`**（可移植、易校验）。  
4. 建议增加 `knowledge_items.deleted_at` 或导入冲突时的稳定 `content_hash` 使用说明（导入 skip 靠 id 还是 hash）。

### M3. 标签休眠与「登录态页」体验

销毁 WebContents 会丢页面内未提交输入（ChatGPT 编辑框）。  
**裁定**：休眠前尽量 `capturePage` 非必须；产品文案注明「休眠会刷新页面」；钉选标签默认不休眠；可选「休眠前确认」仅对脏状态——首版只做钉选豁免 + 文案即可。
